## WRONG BEHAVIOR — Design system violations

### 4. `muted-text` hardcoded color — `globals.css:5588`
**Severity: Wrong** | **Fix type: Quick variable swap**

```css
.muted-text { color: #766e63; }  /* should be var(--text-secondary) or var(--text-tertiary) */
```

Light mode uses a hardcoded warm brown. Dark mode correctly uses `var(--text-secondary)`. Inconsistent across modes; won't track theme-level changes.

---

### 5. `form-message` wrong dark value — `globals.css:5594`
**Severity: Wrong** | **Fix type: Quick variable swap**

```css
.form-message { color: #8d351f; }                           /* not var(--danger) = #c4341a */
body.main-app-dark .form-message { color: var(--brand); }   /* brand orange for an error message */
```

Dark mode error messages render in the same brand orange as CTAs — semantically wrong.

---

### 6. Reviewer Hub timer colors hardcoded — `ReviewerHub.module.css:127–141`
**Severity: Wrong** | **Fix type: Quick variable swap**

```css
.timerWarning { color: #b45309; }   /* not var(--warning) = #c47b1a */
.timerUrgent  { color: #b91c1c; }   /* not var(--danger)  = #c4341a */
:global(body.main-app-dark) .timerWarning { color: #f59e0b; }
:global(body.main-app-dark) .timerUrgent  { color: #ef4444; }
```

Arbitrary Tailwind color values, not design system tokens. Won't follow if `--warning`/`--danger` change.

---

### 7. Admin danger actions styled for dark mode only — `admin.css:527–536`
**Severity: Wrong** | **Fix type: Add light-mode-aware colors**

```css
.admin-danger-action { color: #fca5a5; }        /* Tailwind red-300 — washed out on light bg */
.admin-danger-action:hover { color: #fecaca; }  /* even lighter — nearly invisible on white */
```

"Force refund" on a paid resume is a destructive action that should be unmistakably red. In light mode it barely registers.

---

### 8. Delete button only styled inside a media query — `feed.css:4125`
**Severity: Wrong** | **Fix type: Move outside media query**

Red destructive styles for `.owner-delete-button` are scoped inside a `@media (min-width: ~1100px)` block. Below that breakpoint the shadcn `variant="destructive"` fallback fires — which uses `--destructive` HSL token (shadcn layer), not `--danger`. Inconsistent on mobile.

---

### 9. Leaderboard tag `dark:` classes don't fire — `StackedList.tsx` `tagClass()`
**Severity: Minor-wrong** | **Fix type: Needs design decision**

```ts
// Student
"border-[#D9D0FF] bg-[#F1EDFF] text-[#5137B8] dark:border-[...] dark:bg-[...] dark:text-[...]"
// Career Switcher, Intern, Job Seeker — all hardcoded hex, same pattern
```

Tailwind `dark:` prefix uses `prefers-color-scheme`, but this app switches themes via `body.main-app-dark` class. Dark variants will never fire. All colors are hardcoded hex, not CSS variables.
